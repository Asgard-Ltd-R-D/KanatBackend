Problem. Registering one frame is spread over ~14 symbols in two files and fused with cap.read() in _next_view, so #129's clock cannot start between the read and registration, and 52 loop tests patch five board globals to get past it.

Solution. One registration module, built from the baseline view and the artwork mask: a frame goes in, a view or "lost" comes out, and the re-anchor cadence, gross-fit check, reach tracking and their counters sit behind it.

Problem. _Stream imitates cv2.VideoCapture.read, but the loop reaches past it for index, times, start, stop, report and an isinstance check, so #130's Frame Wait would become one more side channel and one more if live.

Solution. One read returns a frame record; the recording adapter owns seeking and the stride skip, and the stream adapter is today's reader thread with its gap and drop accounting untouched.

Problem. On a recording a Look's "persistence" is an append and the real fold runs once after the loop; on a stream _Announcer folds, judges, assigns Targets and prints in one call. #129's persistence stage would mean different things in each mode.

Solution. One incremental tracker that every Look feeds (points, or lost) and that judges whatever is due; recordings still judge in the same fold order, and the announcer shrinks to print-on-confirm.

  • persistence stage means one thing
  • locality: invariants honoured once
  • live path gains pure tests
  • recording results unchanged
Caveat: keep when corroboration is checked as it is (at judge time live, final position on a recording). Unifying that changes recording results, which ADR-0003's measured thresholds rest on. ADR-0003 window and ADR-0004 no-retraction are untouched.

Problem. The ADR-0005 gate is a convention each __main__ follows its own way: probe gates once per model, so --final-run --model a b spends a Sealed recording and measures nothing; mine_negatives rebuilds it without the log check; the print-scale preflight exists twice.
